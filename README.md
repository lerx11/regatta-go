# Ветер у марины ⛵

Сервис для яхтсменов: живой прогноз ветра по парусным акваториям — сила в узлах,
порывы, направление по румбам, высота волны, баллы Бофорта и автоматический
чек-лист выхода на воду под конкретную погоду.

Один бинарник, **ни одной внешней зависимости** — только стандартная библиотека Go.
Данные берутся из бесплатного [Open-Meteo](https://open-meteo.com/), ключ не нужен.

**Что показывает:** работа с внешним HTTP API, `net/http` и паттерны роутинга Go 1.22+,
параллельные запросы через горутины и `sync.WaitGroup`, потокобезопасный TTL-кеш,
`go:embed` для статики, разбиение на слои (`wind` / `meteo` / `api`), юнит-тесты, Docker.

---

## Демо

Живой стенд: **<https://regatta-go.vercel.app>** — лендинг и API работают на Vercel.

Локально всё поднимается одной командой, см. раздел «Быстрый старт» ниже.

## Быстрый старт

Нужен Go 1.22+ (`brew install go`).

```bash
# из корня проекта
go run .            # сервер поднимется на http://localhost:3000
```

Открыть <http://localhost:3000> — это лендинг, он сам подтянет данные.
Порт меняется переменной `PORT`: `PORT=8080 go run .`

### Тесты

```bash
go test ./...       # 4 пакета тестов: расчёты, клиент, справочник, HTTP-слой
go vet ./...
```

## API

Полное описание эндпоинтов, параметров, кодов ответов и примеры JSON —
в [docs/api.md](docs/api.md).

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/forecast?spot=strogino` | Текущий ветер + 24 часа по часам + чек-лист |
| `GET` | `/api/spots` | Справочник акваторий с координатами |
| `GET` | `/api/scale` | Шкала Бофорта целиком (баллы, диапазоны, рекомендации) |
| `GET` | `/api/trips` | Расписание выходов: дата, акватория, лодка, вместимость, свободные места |
| `POST` | `/api/trips/{id}/book` | Запись в экипаж: JSON `{"name":"…","contact":"…"}` |
| `GET` | `/api/club/trips` | Выходы текущей и следующей недели (нужна cookie клуба) |
| `GET` | `/api/club/trips/{id}` | Экипаж выхода, в том числе после старта (нужна cookie клуба) |
| `POST` | `/api/club/login` | Вход в клуб: JSON `{"password":"…"}` |
| `POST` | `/api/club/logout` | Выход из клуба: сбрасывает cookie |
| `GET` | `/api/health` | Проверка живости |

Параметр `spot` необязателен: без него отдаётся акватория по умолчанию (`strogino`).
Неизвестный `spot` возвращает `404` и JSON `{"error":"..."}`.

## Бронирование выходов

Расписание готовится в коде (`internal/booking`), занятые места хранятся в
[Upstash Redis](https://upstash.com/) через REST API. Нужны две переменные окружения:

```bash
UPSTASH_REDIS_REST_URL=https://<регион>.upstash.io
UPSTASH_REDIS_REST_TOKEN=<токен>
```

Подходят и имена, которые создаёт Vercel-интеграция Upstash:
`KV_REST_API_URL` / `KV_REST_API_TOKEN` (используются, если `UPSTASH_*` не заданы).
Read-only токен не подходит для записи и игнорируется.

Без них сервис запускается как обычно: прогноз работает, `/api/trips` отдаёт
расписание с `storage_configured: false`, а запись отвечает `503` с пояснением.

Схема хранения по каждому выходу (ID вида `2026-11-23-spb-12`):

- `regatta:trip:<id>:booked` — счётчик занятых мест (`INCR`);
- `regatta:trip:<id>:crew` — хеш участников: поле — случайный ID записи,
  значение — JSON с именем, контактом и временем записи.

Последнее место защищено атомарно: `Reserve` выполняет один Lua-скрипт
(`EVAL`), который проверяет счётчик, увеличивает его и пишет участника в хеш.
Redis исполняет скрипт целиком, поэтому два одновременных запроса не могут
занять одно место — второй получает `409`.

В момент старта выход закрывается для новых заявок: сервер отвечает
`409` с `code: "trip_started"`. Публичное расписание переключается на следующую
неделю, но ID выхода не меняется.

### Telegram и клуб

Пошаговая настройка бота, получение chat ID, переменные Vercel и разбор
типичных ошибок — в [docs/telegram.md](docs/telegram.md).

```bash
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_CHAT_ID=<ID личного чата владельца>
CLUB_PASSWORD=<пароль экрана клуба>
```

- После сохранения заявки бот отправляет одно сообщение владельцу: акватория,
  дата и время по Москве, имя и контакт. Если переменные не заданы или Telegram
  недоступен, заявка всё равно сохраняется, а сбой пишется в серверный лог без
  токена и контактов участника.
- Экран клуба — <http://localhost:3000/club>. Без cookie сервер отдаёт страницу
  входа, с ней — «Выходы и экипажи»: текущая и следующая неделя раздельно,
  число заявок и список участников. Пароль задаётся только переменной
  `CLUB_PASSWORD`; в cookie попадает HMAC от него, а не сам пароль.

## Деплой на Vercel

Go на Vercel работает через **Framework Preset `go`**. Он задан явно в
[vercel.json](vercel.json): без него Vercel не запустит Go-сервер, автоматического
определения пресета здесь нет. Дальше Vercel берёт версию Go из директивы `go`
в `go.mod` (сейчас 1.22), находит корневой `main.go`, собирает его обычным `go build`
и запускает бинарник — тот слушает `PORT`, как и требует рантайм.

```bash
npm i -g vercel
vercel --prod
```

Либо через веб-интерфейс: **New Project → Import Git Repository → Deploy**.
Настройки сборки подхватятся из `vercel.json`.

> ⚠️ Go-рантайм на Vercel в статусе **Beta**, но на всех планах, включая бесплатный Hobby.
> Серверлесс-ограничения тут не мешают: постоянных процессов и фоновых кронов нет,
> все зависимости — чистый stdlib.

## Docker

```bash
docker build -t marina-wind .
docker run --rm -p 8080:8080 marina-wind   # http://localhost:8080
```

Финальный образ — `alpine` с непривилегированным пользователем. Тот же контейнер
заводится на любом другом бесплатном хостинге (Fly.io, Railway, Render).

## Как устроено внутри

```
main.go                     точка входа: embed статики, mux, http.Server
web/index.html              лендинг: компас, шкала Бофорта, чек-лист (один файл, без сборки)
internal/wind/              чистая логика: узлы → Бофорт, градусы → румбы, чек-лист
internal/meteo/             клиент Open-Meteo: два запроса параллельно + сборка результата
internal/spots/             справочник акваторий
internal/api/               HTTP-слой, TTL-кеш, сериализация ответов
```

Несколько решений, которые стоит отметить:

- **Параллельные запросы.** Прогноз ветра и прогноз волн уходят одновременно в двух
  горутинах, результат собирается через `sync.WaitGroup`. Ошибка волнового API не
  роняет запрос: для внутренних водоёмов волн просто нет.
- **TTL-кеш на 10 минут.** Не дёргаем бесплатный внешний API на каждый запрос;
  доступ прикрыт `sync.Mutex`.
- **`_ "time/tzdata"`.** База часовых поясов вшита в бинарник — иначе на Vercel и в
  alpine-контейнере `time.LoadLocation("Europe/Moscow")` не работает.
- **Один бинарник.** Лендинг упакован через `go:embed`, поэтому локальный запуск,
  Docker и Vercel работают из одного и того же артефакта.
