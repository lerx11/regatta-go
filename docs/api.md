# API

HTTP-API сервиса «Ветер у марины». Все ответы — JSON в кодировке UTF-8
(`Content-Type: application/json; charset=utf-8`). Ошибки — тоже JSON.

- Локально: `http://localhost:3000`
- Прод: `https://regatta-go.vercel.app`

Запросы к Open-Meteo уходят с сервера, ключ не нужен. CORS-заголовков нет:
API рассчитан на вызовы со страниц этого же сервиса. На неизвестный метод
`http.ServeMux` отвечает `405` с `text/plain`, а не JSON.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера. На Vercel задаётся платформой. |
| `UPSTASH_REDIS_REST_URL` | — | URL базы Upstash Redis (REST). Основное имя. |
| `UPSTASH_REDIS_REST_TOKEN` | — | Токен Upstash с правом записи. Основное имя. |
| `KV_REST_API_URL` | — | Альтернативное имя URL от Vercel-интеграции Upstash. Читается, если `UPSTASH_*` не заданы. |
| `KV_REST_API_TOKEN` | — | Альтернативное имя токена от Vercel-интеграции Upstash. |
| `CLUB_PASSWORD` | — | Пароль закрытого экрана `/club`. Без него вход отвечает `503`. |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота от BotFather. Без пары с `TELEGRAM_CHAT_ID` уведомления выключены. |
| `TELEGRAM_CHAT_ID` | — | ID чата получателя уведомлений о заявках. |

Особенности:

- Read-only токен Upstash и переменные `KV_URL` / `REDIS_URL` не используются —
  по ним нельзя писать.
- Без Redis сервис работает: прогноз отдаётся, `/api/trips` возвращает
  `storage_configured: false`, запись отвечает `503`.
- Без `CLUB_PASSWORD` экран клуба недоступен: `/api/club/trips` отвечает `401`,
  а вход — `503` с подсказкой задать переменную.
- Пошаговая настройка Telegram — в [telegram.md](telegram.md).

Общий вид ошибки:

```json
{ "error": "текст ошибки" }
```

Исключение — попытка записаться на уже начавшийся выход: к ошибке добавляется
машиночитаемый `code`.

```json
{ "error": "Запись закрыта. Выход уже начался", "code": "trip_started" }
```

## GET /api/health

Проверка живости. Без параметров.

`200 OK`

```json
{
  "status": "ok",
  "time": "2026-11-25T00:59:19Z"
}
```

`time` — текущее время сервера в UTC (RFC 3339).

## GET /api/scale

Полная шкала Бофорта. Без параметров.

`200 OK`

```json
{
  "scale": [
    {
      "scale": 0,

}
```

В массиве 13 ступеней:

| Баллы | Название | Узлы | `status` |
|---|---|---|---|
| 0 | Штиль | 0–1 | `calm` |
| 1 | Тихий | 1–3 | `ok` |
| 2 | Лёгкий | 4–6 | `ok` |

## GET /api/forecast

Текущий ветер, прогноз на 24 часа вперёд и чек-лист выхода.

| Параметр | Где | Обязателен | Описание |
|---|---|---|---|
| `spot` | query | нет | Slug акватории. По умолчанию `strogino`. Регистр и пробелы по краям не важны. |

Успех — `200 OK`. Заголовки:

- `X-Cache: HIT` или `MISS` — ответ взят из кеша сервера или получен заново;
- на `MISS` дополнительно приходит `Cache-Control: public, max-age=300`.

Готовый ответ кешируется в памяти сервера на 10 минут отдельно для каждой
акватории.

```bash
curl "http://localhost:3000/api/forecast?spot=sochi"
```


Поля:

| Поле | Описание |
|---|---|
| `timezone` | Часовой пояс точки от Open-Meteo (обычно `Europe/Moscow`). |
| `generated` | Когда сервер собрал ответ, UTC. |
| `current.time`, `current.date` | Местные время и дата текущего среза. |
| `wind_knots`, `gust_knots` | Ветер и порывы в узлах, округление до 0,1. |
| `wind_ms` | Ветер в м/с, округление до 0,1. |
| `direction_deg` | Направление ветра в градусах, целое. |
| `rumb`, `rumb_full` | Короткий (16 румбов) и полный румб. |
| `beaufort`, `beaufort_name` | Баллы Бофорта и название ступени. |
| `sea_state`, `sail_advice`, `sailor_level` | Состояние воды, рекомендация и требуемый уровень. |
| `status` | `calm`, `ok`, `good`, `caution`, `danger`, `closed`. |
| `wave_m`, `wave_rumb`, `wave_period_s` | Волна: высота, направление, период. Только для `coastal`. |
| `hours[]` | До 24 часов вперёд: `time` (RFC 3339), `label`, ветер, порывы, направление, румб, Бофорт, статус, `wave_m` при наличии. |
| `checklist` | 3–10 пунктов, набор зависит от силы ветра. |

Коды ответов:

| Код | Когда | Тело |
|---|---|---|
| `200` | Успех | Прогноз. |
| `404` | Неизвестный `spot` | `{"error":"неизвестная акватория: atlantis"}` |
| `502` | Open-Meteo недоступен или ответил ошибкой | `{"error":"не удалось получить прогноз: …"}` |

Для внутренних водоёмов волновой API не запрашивается, поэтому `wave_m`,
`wave_rumb` и `wave_period_s` в ответе отсутствуют.

## GET /api/trips

Расписание ближайших выходов и число занятых мест. Слотов шесть: у Строгино
два выхода в среду, остальные акватории представлены одним.

Успех — `200 OK`, `Cache-Control: no-store`.

```json
{
  "storage_configured": true,
  "timezone": "Europe/Moscow",
  "trips": [
    {
      "id": "2026-11-30-sochi-10",
      "date": "2026-11-30",
      "label": "пн, 30 ноября",
      "time": "10:00",
      "end": "13:00",
      "spot": "sochi",
      "spot_name": "Сочи",
      "boat": "Яхта 34 фута",
      "capacity": 8,
      "booked": 1,
      "free": 7
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `id` | Стабильный ID выхода: `YYYY-MM-DD-slug-HH`. |
| `date`, `label`, `time` | Дата, подпись для человека, время старта по Москве. |
| `end` | Время окончания, если известно (сейчас задано для всех выходов). |
| `capacity` | Всего мест. |
| `booked`, `free` | Занято и свободно. `null`, если Redis не настроен. |
| `storage_configured` | Можно ли принимать заявки. |
| `timezone` | Всегда `Europe/Moscow`. |

Если Redis не настроен, `booked` и `free` равны `null`, а `storage_configured` —
`false`. Выход остаётся в расписании до момента старта; после старта на его
месте появляется выход следующей недели, а ID начавшегося сохраняется для клуба.

Коды: `200` — успех; `502` — не удалось прочитать занятые места из Redis
(`{"error":"не удалось получить занятые места: …"}`).

## POST /api/trips/{id}/book

Запись в экипаж выхода.

| Параметр | Где | Описание |
|---|---|---|
| `id` | path | ID выхода из `/api/trips`. |
| `name` | JSON body | Имя, от 2 до 80 символов после обрезки пробелов. |
| `contact` | JSON body | Телефон или e-mail, от 5 до 120 символов. |

Тело — не больше 4 КБ.

```bash
curl -X POST "http://localhost:3000/api/trips/2026-11-30-sochi-10/book" \
  -H "Content-Type: application/json" \
  -d '{"name":"Анна Петрова","contact":"+7 900 123-45-67"}'
```

`200 OK` — заявка сохранена:

```json
{
  "participant_id": "4a2cf8929a3ac216",
  "trip_id": "2026-11-30-sochi-10",
  "booked": 1,
  "seats_left": 7
}
```

Гонки за последнее место нет: проверка и занятие места выполняются одним
атомарным Lua-скриптом в Redis. После сохранения сервис отправляет уведомление
в Telegram, если оно настроено; сбой уведомления заявку не отменяет.

Коды ответов:

| Код | Когда | Пример тела |
|---|---|---|
| `200` | Записали | `{"participant_id":"…","trip_id":"…","booked":1,"seats_left":7}` |
| `400` | Битый JSON | `{"error":"некорректный JSON: ожидаются поля name и contact"}` |
| `400` | Не прошла валидация | `{"error":"имя: от 2 до 80 символов"}` или `{"error":"контакт: от 5 до 120 символов — телефон или e-mail"}` |
| `404` | Выхода нет в актуальном расписании | `{"error":"выход не найден или уже прошёл"}` |
| `409` | Свободных мест нет | `{"error":"на этот выход уже нет свободных мест"}` |
| `409` | Выход уже начался | `{"error":"Запись закрыта. Выход уже начался","code":"trip_started"}` |
| `503` | Не настроен Redis | `{"error":"бронирование недоступно: не настроен Upstash Redis (UPSTASH_REDIS_REST_URL и UPSTASH_REDIS_REST_TOKEN)"}` |
| `502` | Ошибка записи в Redis | `{"error":"не удалось сохранить запись: …"}` |

Два разных `409` различаются по полю `code`: `trip_started` — старт наступил;
без `code` — закончились места.

## POST /api/club/login

Вход в закрытый экран клуба. Тело — не больше 4 КБ.

```json
{ "password": "пароль из CLUB_PASSWORD" }
```

`200 OK` — пароль верный, в ответе выставляется cookie:

```json
{ "ok": true }
```

Cookie `regatta_club`:

- `HttpOnly`, `SameSite=Lax`, `Path=/`, срок жизни 12 часов;
- `Secure`, если запрос пришёл по HTTPS;
- содержит HMAC от пароля, а не сам пароль. Смена `CLUB_PASSWORD` сразу
  инвалидирует старые cookie.

Коды:

| Код | Когда | Тело |
|---|---|---|
| `200` | Верный пароль | `{"ok":true}` и `Set-Cookie` |
| `400` | Битый JSON | `{"error":"некорректный JSON: ожидается поле password"}` |
| `401` | Неверный пароль | `{"error":"Неверный пароль"}` |
| `503` | `CLUB_PASSWORD` не задан | `{"error":"вход в клуб не настроен: задайте CLUB_PASSWORD"}` |

## GET /api/club/trips

Выходы текущей и следующей недели. Нужна cookie клуба (см. вход).

Успех — `200 OK`, `Cache-Control: no-store`.

```json
{
  "timezone": "Europe/Moscow",
  "current": [
    {
      "id": "2026-11-23-sochi-10",
      "date": "2026-11-23",
      "label": "пн, 23 ноября",
      "time": "10:00",
      "end": "13:00",
      "spot": "sochi",
      "spot_name": "Сочи",
      "boat": "Яхта 34 фута",
      "capacity": 8,
      "started": true,
      "status": "finished",
      "booked": 0
    }
  ],
  "next": [
    {
      "id": "2026-11-30-sochi-10",
      "date": "2026-11-30",
      "label": "пн, 30 ноября",
      "time": "10:00",
      "end": "13:00",
      "spot": "sochi",
      "spot_name": "Сочи",
      "boat": "Яхта 34 фута",
      "capacity": 8,
      "started": false,
      "status": "",
      "booked": 1
    }
  ]
}
```

Неделя начинается в понедельник по Москве. В `current` попадают и уже
начавшиеся выходы; в `next` — те же дни следующей недели.

Поля `ClubTrip` совпадают с `/api/trips`, плюс:

| Поле | Описание |
|---|---|
| `started` | Время старта наступило. |
| `status` | `""` — ещё не начался; `live` — идёт; `finished` — завершён; `closed` — начался, но время окончания неизвестно. |
| `booked` | Число заявок. |

Правила `status`:

- до старта — метки нет (`""`);
- если известно время окончания (`end`): от старта до окончания — `live`,
  после — `finished`;
- если окончание неизвестно: с момента старта — `closed`.

Коды:

| Код | Когда | Тело |
|---|---|---|
| `200` | Успех | `current`, `next`, `timezone` |
| `401` | Нет или протухла cookie | `{"error":"нужен пароль клуба"}` |
| `503` | Не настроен Redis | `{"error":"данные клуба недоступны: не настроен Upstash Redis"}` |
| `502` | Ошибка Upstash | `{"error":"не удалось загрузить данные клуба"}` |

## GET /api/club/trips/{id}

Карточка выхода и список участников. Нужна cookie клуба. Доступна и после
старта — ID выхода не меняется.

`200 OK`

```json
{
  "id": "2026-11-30-sochi-10",
  "date": "2026-11-30",
  "label": "пн, 30 ноября",
  "time": "10:00",
  "end": "13:00",
  "spot": "sochi",
  "spot_name": "Сочи",
  "boat": "Яхта 34 фута",
  "capacity": 8,
  "started": false,
  "status": "",
  "booked": 1,
  "crew": [
    {
      "participant_id": "4a2cf8929a3ac216",
      "name": "Анна Петрова",
      "contact": "+7 900 123-45-67",
      "at": "2026-11-25T00:59:30Z"
    }
  ]
}
```

`crew` отсортирован по времени записи. `at` — время заявки в UTC.
Если заявок нет, `crew` — пустой массив, а не `null`.

Коды:

| Код | Когда | Тело |
|---|---|---|
| `200` | Успех | Карточка и `crew` |
| `401` | Нет или протухла cookie | `{"error":"нужен пароль клуба"}` |
| `404` | Выхода нет в текущей и следующей неделе | `{"error":"выход не найден"}` |
| `503` | Не настроен Redis | `{"error":"данные клуба недоступны: не настроен Upstash Redis"}` |
| `502` | Ошибка Upstash | `{"error":"не удалось загрузить данные клуба"}` |

## HTML-страницы

| Метод | Путь | Что отдаёт |
|---|---|---|
| `GET` | `/` | Лендинг с прогнозом, расписанием и формой записи. |
| `GET` | `/club` | Без cookie — страницу входа; с cookie — экран «Выходы и экипажи». `Cache-Control: no-store`. |
| `GET` | `/club.html` | Редирект `302` на `/club`. |

Прямой доступ к файлам экрана клуба закрыт: только через `/club`.
