# Telegram-уведомления о заявках

После каждой новой заявки сервис отправляет владельцу одно сообщение через
Telegram Bot API. Уведомление — вспомогательное: сначала заявка сохраняется
в Redis, и только потом уходит сообщение. Если Telegram недоступен или не
настроен, заявка остаётся в силе.

## Что приходит в сообщении

```
Новая заявка на выход
Акватория: Сочи
Дата: 30.11.2026, 10:00 МСК
Имя: Анна Петрова
Контакт: +7 900 123-45-67
```

Дата — в формате `ДД.ММ.ГГГГ`, время — по Москве. В сообщении нет ничего,
кроме выхода и данных участника.

## Как это устроено

- Переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` читаются один раз при
  старте. Нужны **обе**: если задана только одна, уведомления выключены.
- Запрос идёт на `https://api.telegram.org/bot<TOKEN>/sendMessage` с таймаутом
  6 секунд, без превью ссылок.
- При старте в лог пишется `уведомления: Telegram подключён` либо
  `уведомления: TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID не заданы, отправка отключена`.
- При сбое в лог попадает только ID выхода и текст ошибки:
  `уведомление о заявке на выход <id> не отправлено: …`. Токен и контакт
  участника в лог не попадают.

---

## Шаг 1. Создать бота в BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя бота (видно пользователям), например `Ветер у марины`.
3. Введите username, он должен заканчиваться на `bot`, например
   `marina_wind_notify_bot`. Если занято — попробуйте другой.
4. BotFather пришлёт токен вида `123456789:AA…`. Это секрет: он даёт полный
   доступ к боту. Не пересылайте его в чаты и не коммитьте в репозиторий.
5. При необходимости настройте бота там же: `/setdescription`, `/setuserpic`.

Сохраните токен — он понадобится на шаге 3.

## Шаг 2. Узнать chat ID

Chat ID — числовой идентификатор чата, куда бот будет писать. Он зависит от
того, куда должны приходить уведомления.

### Личный чат

1. Откройте своего бота по ссылке `https://t.me/<username>` и нажмите **Start**
   (или отправьте любое сообщение — бот не может писать первым).
2. Запросите обновления:

```bash
curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getUpdates"
```

3. В ответе найдите `"chat":{"id":123456789,…}` — это и есть `TELEGRAM_CHAT_ID`.

Альтернатива без `getUpdates`: напишите [@userinfobot](https://t.me/userinfobot),
он пришлёт ваш ID.

### Группа

1. Добавьте бота в группу.
2. Отправьте в группе сообщение, адресованное боту: `@<username> привет`.
3. Снова вызовите `getUpdates` и возьмите `chat.id` из ответа. У групп ID
   отрицательный, например `-1001234567890`.

Если бот не видит обычные сообщения в группе, у него включён privacy mode.
В BotFather: `/setprivacy` → выберите бота → **Disable**, после чего удалите
бота из группы и добавьте заново.

### Канал

1. Добавьте бота администратором канала с правом публикации.
2. В `TELEGRAM_CHAT_ID` можно указать числовой ID канала (начинается с `-100`)
   или публичный `@username` канала.

## Шаг 3. Добавить переменные в Vercel

1. Откройте проект в Vercel → **Settings** → **Environment Variables**.
2. Добавьте две переменные:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из BotFather |
| `TELEGRAM_CHAT_ID` | ID чата из шага 2 |

3. Отметьте окружения, где нужны уведомления: как минимум **Production**.
   Если хотите проверять и на превью-деплоях — добавьте **Preview**.
4. Сохраните и **перезапустите деплой**: **Deployments** → у последнего
   деплоя **⋯** → **Redeploy**. Переменные применяются только к новым
   деплоям, уже собранный сайт продолжит работать со старым окружением.

Токен в интерфейсе Vercel маскируется; посмотреть значение повторно нельзя,
только заменить.

## Шаг 4. Проверить, что уведомление приходит

### Локально

Токен и chat ID передаются процессу через окружение. Файл `.env` сервис сам
не читает — нужен `export`:

```bash
export TELEGRAM_BOT_TOKEN="<токен>"
export TELEGRAM_CHAT_ID="<chat id>"
go run .
```

В логе должно появиться `уведомления: Telegram подключён`. Затем откройте
<http://localhost:3000>, запишитесь на любой выход и дождитесь сообщения.

Быстрая проверка самого канала, без сервиса:

```bash
curl -s -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  -H "Content-Type: application/json" \
  -d "{\"chat_id\":\"${TELEGRAM_CHAT_ID}\",\"text\":\"Проверка уведомлений\"}"
```

Успех — `{"ok":true,…}` и сообщение в чате.

### На проде

1. Убедитесь, что после добавления переменных был **Redeploy**.
2. Откройте сайт, отправьте тестовую заявку на ближайший выход.
3. Проверьте сообщение в Telegram.
4. Если сообщения нет, посмотрите логи: в Vercel — **Deployments** → последний
   деплой → **Logs**, либо из терминала `vercel logs <адрес-деплоя>`.
   Там будет либо `Telegram подключён`, либо строка
   `уведомление о заявке на выход … не отправлено: …`.

Уведомление отправляется только на **новую** заявку: обновление страницы или
повторный просмотр списка его не вызывают.

## Если уведомление не приходит

| Симптом | Причина | Что делать |
|---|---|---|
| В логе `TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID не заданы` | Переменные не добавлены, задана только одна или деплой не пересобран | Проверьте обе переменные в нужном окружении и сделайте Redeploy |
| В логе `telegram: HTTP 401: Unauthorized` | Токен неверный или отозван | Скопируйте токен заново в BotFather (`/mybots` → **API Token**) и обновите переменную |
| `telegram: HTTP 400: Bad Request: chat not found` | Неверный `chat_id`, бот не запущен или удалён из чата | Нажмите Start у бота, перепроверьте ID через `getUpdates` |
| `telegram: HTTP 403: Forbidden: bot was blocked by the user` | Пользователь заблокировал бота | Разблокируйте бота в Telegram |
| `telegram: HTTP 403: Forbidden: bot is not a member…` | Бот не добавлен в канал или не админ | Добавьте бота администратором |
| `telegram: запрос не выполнен` | Нет сети, таймаут 6 с или Telegram недоступен | Проверьте сеть и повторите; заявка уже сохранена |
| В группе бот молчит, в личке работает | Включён privacy mode | `/setprivacy` → Disable и заново добавьте бота в группу |
| Сообщения нет, ошибок в логе нет | Смотрите не тот деплой или тестовую заявку не создавали | Откройте актуальный URL и отправьте новую заявку |

Во всех случаях заявка уже записана в Redis: сбой уведомления её не отменяет.
Проверить список участников можно на экране клуба `/club`.

## Безопасность

- Токен — это пароль бота. Храните его только в переменных окружения Vercel
  (или в локальном шелле), не в репозитории и не в скриншотах.
- Если токен попал в чужие руки: BotFather → `/revoke` → выберите бота.
  BotFather выдаст новый токен, старый перестанет работать. Замените значение
  в Vercel и сделайте Redeploy.
- Сменив `TELEGRAM_CHAT_ID`, вы перенаправите уведомления в другой чат; старые
  сообщения останутся в прежнем.
